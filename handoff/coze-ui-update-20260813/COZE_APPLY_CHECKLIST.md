# Coze 版本升级执行清单

## 1. 升级前检查

1. 在 Coze 项目文件区确认存在以下 6 个文件：
   - `templates/base.html`
   - `templates/report.html`
   - `templates/teacher_analytics.html`
   - `templates/teacher_dashboard.html`
   - `static/platform.js`
   - `static/quantum-platform.css`
2. 打开 `templates/base.html`，确认使用 `url_for('static', filename='platform.js')` 和 `quantum-platform.css`。
3. 搜索是否存在旧 CSS、旧模板或 iframe 入口。若存在平行 UI，停止覆盖并先确定唯一入口。
4. 记录当前可访问地址、版本时间和当前能正常登录的学生/教师测试账号；不要在文档或截图中记录密码。

## 2. 备份

覆盖前把当前 6 个目标文件下载到独立备份目录，例如：

`backup-before-mobile-ui-YYYYMMDD-HHMM/`

如果 Coze 支持版本快照或复制项目，先创建一个可回滚版本。此次没有数据库迁移，但仍不得删除数据库或上传文件。

## 3. 覆盖顺序

推荐一次性上传 `coze-ui-update-overwrite-20260813.zip` 并保持目录结构。若只能逐个修改：

1. `static/platform.js`
2. `static/quantum-platform.css`
3. `templates/report.html`
4. `templates/teacher_analytics.html`
5. `templates/teacher_dashboard.html`
6. 最后更新 `templates/base.html`

最后更新 `base.html` 是为了避免页面先引用到尚未上传的新交互逻辑。

规范文档和打包脚本不影响运行，可在运行文件确认后再同步。

## 4. 重启与缓存

1. 在 Coze 部署页面重新构建或重启应用。
2. 确认构建日志没有 Jinja 模板错误、JavaScript 语法错误或静态文件 404。
3. 浏览器使用无痕窗口访问，或强制刷新清除旧静态资源。
4. 查看页面源码，确认静态资源 URL 包含 `20260813-multidevice-v1`。

## 5. 必测流程

### 公共与学生端

1. 登录页可正常登录。
2. 登录后每页可见“返回上级 / 回到首页”。
3. 学生首页、我的实验、报告与荣誉、实验工作台无横向溢出。
4. 实验工作台的上一步/下一步可连续切换。
5. AI 答疑抽屉支持关闭按钮、遮罩和 Escape。
6. 正式报告的“报告目录”可打开，选择章节后抽屉关闭并定位正文。

### 教师端

1. 审核队列“筛选与排序”打开抽屉，搜索和筛选实际生效。
2. 学情观测“筛选”打开抽屉，应用筛选后数据刷新。
3. 创建班级等模态可通过关闭按钮、遮罩和 Escape 关闭。
4. 删除、下架、发布等危险操作先出现统一确认模态，取消时不得提交。
5. AI 学情抽屉支持遮罩关闭和焦点回到入口。

### 多端

至少检查：

- 桌面：1440×900；
- 平板横屏：1024×768；
- 平板竖屏：768×1024；
- 手机：390×844。

手机端重点确认按钮不低于 44px、输入框不触发异常页面缩放、抽屉转为底部面板、表格转为字段卡片。

## 6. 异常与离线

1. 清空创建班级名称并提交，应聚焦必填字段且显示错误通知。
2. 浏览器切换离线后，应显示离线状态条；不得提示保存成功。
3. 恢复联网后状态条消失，用户可重新提交。
4. 若静态文件 404，检查上传目录结构和 `base.html` 资源路径。
5. 若页面样式新旧混合，确认静态缓存已清除且没有第二套 CSS。

## 7. 回滚

满足任一条件立即回滚：

- 登录、学生实验或教师审核主流程无法进入；
- 页面持续出现 JS 异常；
- 模态无法关闭或遮挡核心操作；
- 学生页面出现教师评分、内部评语等越权信息；
- Coze 版本与本包不是同一 Flask/Jinja 架构。

回滚时恢复升级前备份的 6 个文件，重启应用并再次清除缓存。由于本次不修改数据库，不需要执行数据库回滚。
