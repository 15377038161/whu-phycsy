# 全平台 UI 视觉标准 V1

本文件是学生端、教师端和登录页共同遵循的文字、图标与页面尺度规范。实现唯一位于 `static/quantum-platform.css` 的 `Platform UI V9` 区块；业务模板不得通过行内字号或新增平行 CSS 绕开本规范。

## 1. 现状盘点与已消除的不一致

本轮扫描 `templates/` 的 14 个模板与 `static/quantum-platform.css`，基线结果如下：

- 页面共有 62 个 `H1–H6` 标题节点，旧样式存在 18、19、20、21、22、24、25、26、27、28、30、32、34、36、38、40、44、46 px 以及 `clamp()` 等多套标题字号。
- CSS 中存在 120 处字体相关规则；正文和辅助文字集中但未统一地使用 8–13 px，其中 8 px 41 处、9 px 78 处、10 px 59 处、11 px 39 处、12 px 38 处。
- 旧字体混用 `Inter`、`PingFang SC`、`Microsoft YaHei`、Georgia、`Songti SC`、SimSun、SimHei、Times New Roman 与 Consolas，缺少明确的界面/标题/数字/代码职责边界。
- Lucide 图标出现至少 12、13、14、15、16、17、18、20、22、24、28、30、34、38 px 多套尺寸，部分仅设置宽度、依赖继承高度。
- “审核队列”和“学情观测”虽然外层宽度相同，但横向内边距不同，导致两个二级页面的内容边界和视觉尺度不一致。

上述差异现已由统一变量和语义选择器收口。证书、A4 报告正文、实验数据图等内容型视觉允许使用其业务专属比例，但页面导航、操作控件和标题层级必须遵循本文件。

## 2. 字体栈

| 用途 | 变量 | 字体栈 |
| --- | --- | --- |
| 界面正文 | `--ui-font-body` | Inter, PingFang SC, Microsoft YaHei, Noto Sans CJK SC, Arial, sans-serif |
| 页面标题 | `--ui-font-display` | Songti SC, STSong, Georgia, Times New Roman, serif |
| 数字指标 | `--ui-font-number` | Inter, Helvetica Neue, Arial, sans-serif；使用等宽数字 |
| 代码/原始数据 | `--ui-font-code` | Consolas, SFMono-Regular, Liberation Mono, monospace |

SimHei 仅用于 PDF 中文渲染；SimSun/Times New Roman 仅用于 A4 学术报告内容，不作为界面字体。

## 3. 文字层级

| 层级 | 桌面 | 手机 | 行高 | 字重 | 典型用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| 页面标题 / H1 | 42 px | 34 px | 1.2 | 500 | 页面唯一主标题 |
| 区块标题 / H2 | 26 px | 24 px | 1.3 | 500 | 卡片组、工作区标题 |
| 卡片标题 / H3 | 20 px | 18 px | 1.4 | 500 | 实验卡、表单小节 |
| 小标题 / H4–H6 | 17 px | 17 px | 1.4 | 600 | 局部说明标题 |
| 正文 | 14 px | 14 px | 1.7 | 400 | 说明、表格内容 |
| 控件文字 | 14 px | 14 px | 1.4 | 700 | 按钮、页签、文本链接 |
| 标签 | 12 px | 12 px | 1.5 | 700 | 表单标签、表头 |
| 辅助文字 | 11 px | 11 px | 1.5 | 400/700 | 时间、状态补充、说明 |

页面不得再新增 8 px、9 px 的业务文字。数字统一加 `.teacher-number` 或对应数字语义类，启用 `tabular-nums lining-nums`。

## 4. 图标规格

| 类别 | 尺寸 | 使用范围 |
| --- | ---: | --- |
| 导航图标 | 16 × 16 px | 顶部导航、二级导航 |
| 操作图标 | 16 × 16 px | 按钮、文本链接、输入框操作 |
| 业务状态图标 | 20 × 20 px | 指标卡、预警、状态摘要 |
| 功能强调图标 | 24 × 24 px | 空状态、区块主图标 |

所有 Lucide 图标固定宽高比 1:1、`stroke-width: 2`，不得只设置单边尺寸。证书图案和业务插画不属于功能图标，不受上述像素尺寸限制。

## 5. 页面与响应式

- 教师审核队列与学情观测共用 `1328 px` 最大内容宽度和完全一致的横向边界。
- 桌面页面两侧至少 32 px；平板页面两侧 18 px；手机页面两侧 10 px。
- 桌面复杂数据允许多栏；`≤900 px` 合并操作区；`≤680 px` 表格转字段卡片、关键按钮高度至少 48 px。
- 页面级横向溢出必须为 0；确需横向浏览的展廊、题目列表和表格容器必须局部滚动。

## 6. 开发与验收规则

- 新页面优先复用现有页面标题、区块标题、按钮、状态、表格和图标类，不新增孤立字号。
- 业务模板不得出现行内 `font-size`、`font-family` 或 Lucide 宽高声明。
- 每次 UI 修改运行 `python scripts/verify_project.py`、`pytest -q`、真实浏览器桌面/平板/手机检查、PDF 测试、Docker 配置检查和交付包秘密扫描。
- 跨浏览器回归使用 `tests/ui_visual_audit.mjs`，通过 `UI_BROWSER=chromium|firefox|webkit` 分别执行。
- 必测视口：1440×900、1024×768、768×1024、390×844；审核队列与学情观测的页面标题、二级导航和内容左右边界必须逐项相同。

## 7. 色值与视觉语义

| 语义 | 变量/参考值 | 使用边界 |
| --- | --- | --- |
| 武大蓝 | `--blue` / `#002554` | 主标题、主导航、主按钮、强品牌区域 |
| 玉石青 | `--jade` / `#0a7d7a` | 当前进度、完成状态、焦点与非阻断成功反馈 |
| 克制金 | `--gold` / `#b98b43` | 编号、纪念性强调、少量辅助状态，不作大面积正文底色 |
| 樱花粉 | `--pink` | 学生纪念视觉与氛围装饰，不表达错误或审核结论 |
| 暖白纸色 | `--paper` | 页面、卡片和弹层主体背景 |
| 错误红 | `--red` | 删除、失败、字段错误和危险确认 |
| 分隔线 | `--line` | 卡片、表格、输入框与层级分隔 |
| 辅助文字 | `--muted` | 时间、解释和低优先级信息；必须满足可读对比度 |

普通正文与背景的对比度至少为 4.5:1，大号文字至少为 3:1；颜色不能作为唯一状态编码，必须同步提供文字、图标或结构提示。

## 8. 间距、圆角与页面网格

- 基础间距单位为 4 px；常用间距为 8、12、16、24、32、40、48、64 px。
- 桌面内容最大宽度使用 `--ui-content-wide`，宽屏不无限拉伸正文；平板与手机按第 5 节收缩页边距。
- 卡片内部留白桌面 20–28 px、手机 14–18 px；相邻业务区块桌面 18–24 px、手机 10–16 px。
- 控件圆角 7–10 px，卡片与弹层 10–18 px；同一层级不得混用大量不同圆角。
- 正文最佳行宽为 42–72 个中文字符；移动端说明文字不超过 42 字符宽，长说明进入抽屉、分步页或折叠区。

## 9. 按键与基础导航

| 类型 | 用途 | 标准 |
| --- | --- | --- |
| 主按钮 `.primary` | 当前页面唯一首要动作 | 武大蓝实底；一个操作区最多一个 |
| 次按钮 `.secondary-button` | 返回、筛选、导出、取消 | 暖白或浅色底、清晰描边 |
| 危险按钮 `.danger-button` | 删除、撤回、下架 | 错误红语义；执行前进入确认模态 |
| AI 按钮 `.ai-button` | 明确触发 AI 生成或分析 | 与普通主按钮区分，但不得取代人工确认 |
| 文本链接 `.text-link` | 页面间轻量跳转 | 带方向图标或明确动作文字 |

- 所有登录后页面统一显示 `.global-page-tools`，包含“返回上级”和“回到首页”；返回键只回到同源历史，否则使用角色首页兜底。
- 控件最小触控尺寸桌面 34×34 px、移动端 44×44 px；关键按钮移动端至少 48 px 高。
- 实验学习流程沿用 `.workspace-step-nav`；实验编辑流程沿用 `.editor-flow-nav`。上一步、当前步骤和下一步位置固定，最后一步将“下一步”替换为明确的保存/提交动作。
- 删除键只在拥有删除语义的业务对象旁出现，不为不存在删除语义的内容页制造空操作。

## 10. 响应式与内容分层

| 断点 | 布局原则 |
| --- | --- |
| `> 1024 px` | 宽屏多栏、右侧抽屉、完整表格；正文保持最大宽度 |
| `721–1024 px` | 减少并列列数，复杂筛选进入右侧抽屉，表格允许局部滚动 |
| `≤ 720 px` | 单列主流程、底部面板式抽屉、字段卡片、16 px 表单输入字体 |
| `≤ 680 px` | 32/22/17 px 标题层级，44–48 px 触控控件，10 px 页面边距 |

- 主页面只保留当前任务、关键状态和首要动作；筛选、目录、帮助、长列表与辅助信息进入抽屉。
- 多步骤任务使用分页/步骤切换，不在手机端同时展开所有步骤。
- 表格在小屏转为含 `data-label` 的字段卡片；确需横向比较时只允许表格容器局部滚动，页面本身不得横向溢出。
- 不通过复制模板或新增移动端 CSS 文件实现适配，所有端共用业务 DOM、`static/platform.js` 和 `static/quantum-platform.css`。

## 11. 弹层规范

- 抽屉：筛选、目录、AI 会话、长列表和辅助流程；桌面/平板右侧滑入，手机转为底部面板。
- 模态：仅用于不可逆、改变正式状态或必须完成后才能继续的强确认场景。
- 通知：保存成功、同步完成、字段错误、网络中断等非阻断反馈；默认 5 秒自动消失且可手动关闭。
- 所有弹层必须支持明确关闭按钮、遮罩点击关闭、Escape、焦点进入、键盘焦点约束、关闭后焦点回到触发器；业务明确禁止遮罩关闭时使用 `data-backdrop-close="false"`。
- 弹层标题必须由 `aria-labelledby` 关联，正文由 `aria-describedby` 关联；不得在同一时刻打开两个竞争焦点的弹层。

## 12. 表单、加载、空状态与异常

- 每个字段均有可见标签；占位文本只作示例，不替代标签。必填、长度、格式与范围使用原生约束和服务端二次校验。
- 无效字段设置 `aria-invalid="true"`、错误边框并自动聚焦；错误通知描述修正方向，不只写“操作失败”。
- 表单提交后触发按钮进入 `aria-busy="true"` 和加载态，防止重复提交；请求失败后必须恢复可操作状态。
- 数据列表必须具备加载、空、错误和正常四态；空状态说明“为什么为空”和“下一步能做什么”。
- AI、拟合、上传和导出显示阶段化进度与超时错误，不使用永久旋转的无解释 Loading。
- HTTP/API 异常统一优先读取结构化 `error` 与 `code`，认证失败引导重新登录，冲突错误展示刷新/保留/重试路径。

## 13. 无障碍、动效与离线

- 页面语言为 `zh-CN`，每页只有一个主 `h1`；标题不得跳级。主区域为 `#mainContent`，提供“跳到主要内容”链接。
- 当前导航设置 `aria-current="page"`；图标按钮必须有中文 `aria-label`；装饰层全部 `aria-hidden="true"` 且不接收点击。
- 全流程支持键盘 Tab、Shift+Tab、Enter、Space、Escape；焦点样式不得被移除。
- 响应 `prefers-reduced-motion`：关闭装饰动画、平滑滚动和非必要转场；响应 `prefers-contrast: more` 提升边框与控件对比。
- 页面切换只使用 200–280 ms 的透明度/轻位移过渡，不对校园建筑、正文或关键控件做持续位移动画。
- 离线时显示全局状态条，允许继续阅读已加载内容；保存、提交、AI 与服务端导出必须明确提示联网重试，不伪造成功。当前版本不承诺离线写入或后台同步。

## 双层闯关新增验收

学生选关面板、步骤小关卡、资料入口、数据表和奖状弹窗必须使用与首页一致的正文/控件字号（15px 基准），桌面和移动端均可读；Coze 同步版本不得另建平行样式。

- 实验工作台固定为实验原理、预习测试、实验闯关、实验报告四个页签；视频和课件只出现在原理页。
- 实验闯关桌面端使用左侧时间线加右侧单步纸张，移动端时间线横向滚动；一次只显示一个小关，禁止重新堆叠全部步骤。
- 当前关使用武大蓝，已完成关使用玉石青，未开放关降低对比并禁用；状态不能只依赖颜色。
- 数据表允许自身横向滚动但不得导致页面横向溢出；拟合加载必须展示计算引擎、科学组件和字体三个阶段，失败时紧邻显示 Excel 兜底入口。
- 报告同步冲突必须让学生明确选择刷新或保留手工修改，不能以通知后自动覆盖。

## 14. 验收清单

1. 1440×900、1024×768、768×1024、390×844 均无页面级横向溢出。
2. 所有登录后页面可见返回上级与回到首页；实验/编辑流程可通过上一步与下一步完整到达。
3. 抽屉、模态、通知分别验证按钮关闭、遮罩关闭、Escape、焦点回归和触控尺寸。
4. 键盘可到达所有核心动作；放大至 200% 后内容与操作不丢失。
5. 模拟离线、400、401/403、404、409、413、429、500/503 和超时，页面给出可恢复路径。
6. 运行 `python scripts/verify_project.py`、`pytest -q` 与真实浏览器审计；UI 修改同时检查 PDF、Docker 配置和交付包秘密扫描。
