1

界面布局审查与优化

1.1 信息密度问题

问题 P0

教师端首页常将课程列表、学生统计、待办事项、通知公告堆叠在同一视口内，信息密度过高。单屏元素超过 15 个独立信息块时，认知负荷急剧上升，教师难以快速定位关键操作入口。

优化方案

采用「卡片分区 + 折叠面板」策略。首屏只保留 4 个核心区块：①数据概览（KPI 卡片行）②快捷操作（3-4 个主入口）③今日待办（最多 5 条）④最近活动流。次要信息收入 Tab 或折叠面板。单屏信息块控制在 7±2 个。

1.2 空间分配不合理

问题 P0

侧边导航栏占比过大（>220px），主内容区被压缩；同时导航项间距不统一，部分项高度 36px、部分 44px，视觉节奏混乱。表格区域留白过多或过少，缺乏一致的间距体系。

优化方案 — 统一间距体系（8px 基准）
区域当前值建议值说明
侧边导航宽度220px+200px（折叠态 64px）支持折叠，释放主内容空间
导航项高度36~44px 不统一40px 统一含 8px 上下 padding
导航项间距0~8px 不统一0px（紧凑排列）用分隔线区分组，不用间距
主内容区内边距16~32px 不统一24px上下 24px，左右 32px
卡片间距12~24px 不统一16px统一 gap: 16px
表格行高32~48px 不统一44px保证可点击区域 ≥ 44px
页面最大宽度无限制1440px 居中超宽屏下避免内容拉伸

1.3 元素排列问题

问题 P1

操作按钮位置不一致：部分页面将主操作按钮放在右上角，部分放在表格上方，部分放在底部。筛选器与表格的从属关系不明确，用户不确定筛选结果是否已应用到当前表格。

优化方案 — 统一布局模式

列表页标准布局：页面标题 → 筛选器栏（与表格紧邻，视觉同组）→ 操作按钮栏（主操作右对齐）→ 数据表格 → 分页器。筛选器与表格之间不超过 8px 间距，用同色背景区域包裹表示从属关系。

详情页标准布局：面包屑导航 → 页面标题 + 主操作按钮（右上角）→ 标签页 → 内容区。主操作按钮固定在标题行右侧，不随内容滚动。

2

视觉层次与配色规范

2.1 视觉层次不清晰

问题 P0

标题、正文、辅助文字的字号差异不足（如 14px vs 13px），用户难以快速区分信息层级。卡片标题与卡片内容的字重相同，缺少视觉锚点。数据卡片中数值和标签的对比度不够。

优化方案 — 五级文字层次体系
  • H1 页面标题 24px / 700 / #1a202c / 行高 1.3
  • H2 区块标题 18px / 600 / #1a202c / 行高 1.4
  • H3 卡片标题 15px / 600 / #2d3748 / 行高 1.5
  • Body 正文 14px / 400 / #4a5568 / 行高 1.6
  • Caption 辅助 12px / 400 / #a0aec0 / 行高 1.5

数据卡片中的数值应使用 28px / 700，标签使用 12px / 400，形成强烈对比。

2.2 配色方案不协调

问题 P0

当前使用了过多强调色（蓝色、绿色、橙色、红色、紫色同时出现），缺乏统一的主色调。状态色使用随意（如成功状态有时用绿色有时用蓝色），语义不明确。背景色层次过多（白、灰白、浅灰、浅蓝），视觉碎片化。

优化方案 — 6:3:1 配色比例 + 语义化色彩系统

主色占比 60%，辅助色 30%，强调色 10%。整个系统只使用一个品牌主色（蓝色系），状态色严格语义化。

交互元素统一性规范

3.1 按钮规范

问题 P0

按钮样式混乱：主操作按钮有实心蓝、实心绿、实心深蓝三种；次要按钮有描边白底、描边灰底、纯文字三种；圆角有 4px、6px、8px 三种。同一页面的「提交」和「保存」按钮视觉权重不一致。

优化方案 — 四级按钮体系
层级样式规格使用场景
Primary 实心 · 品牌蓝 bg:#2563EB · color:#FFF · radius:8px · h:36px · px:20 每页仅 1 个主操作（提交/创建/保存）
Secondary 描边 · 白底蓝字 bg:#FFF · border:1px #2563EB · color:#2563EB · radius:8px · h:36px 次要操作（取消/编辑/导出）
Tertiary 纯文字 · 蓝色 bg:transparent · color:#2563EB · h:32px 表格内操作（查看/编辑/删除）
Danger 实心 · 红色 bg:#EF4444 · color:#FFF · radius:8px · h:36px 危险操作（删除/撤销），需二次确认

按钮字号统一 14px / 500。Hover 态：Primary 加 10% 深度 (#1D4ED8)；Secondary 背景变 #EFF6FF。禁用态：opacity: 0.5 + cursor: not-allowed。

3.2 表单规范

问题 P1

输入框高度不统一（32px、36px、40px 混用）；标签位置有左对齐和顶部对齐两种；必填标记有的用红色 *、有的用文字「必填」；错误提示位置有在输入框下方、右侧、上方三种。

优化方案 — 统一表单规范
属性规范值说明
输入框高度36px所有 input/select 统一
输入框圆角6px比按钮略小，区分层级
输入框边框1px solid #E2E8F0默认态
聚焦态边框1px solid #2563EB + shadow0 0 0 3px rgba(37,99,235,0.12)
错误态边框1px solid #EF4444错误提示紧跟输入框下方
标签位置顶部对齐label 在 input 上方，间距 6px
标签字号14px / 500 / #4A5568统一字重
必填标记红色 * 在标签后统一用 *，不用文字
错误提示12px / #EF4444 / 输入框下方带红色圆点图标
表单间距字段间 20pxlabel+input 作为一个整体

3.3 导航规范

问题 P1

侧边导航的选中态、Hover 态、默认态视觉差异不够明显；导航图标风格不统一（有的线性、有的面性）；面包屑导航缺失，用户在深层页面无法快速返回。

优化方案
状态背景文字色说明
默认态transparent#4A556814px / 400
Hover 态#F1F5F9#1A202C背景变浅灰
选中态#DBEAFE#2563EB左侧 3px 蓝色竖线 + 14px / 600
禁用态transparent#A0AEC0cursor: not-allowed

导航图标统一使用 20px 线性图标（stroke-width: 1.5）。所有页面添加面包屑导航（Home / 模块 / 子页面），可点击返回。

4

用户体验改进方案

4.1 操作流程痛点

问题 P0

创建实验/作业流程过长：需要经过 5-6 步才能完成创建（选择类型 → 填写基本信息 → 设置参数 → 选择班级 → 设置时间 → 确认发布），且无法返回上一步修改，只能取消重填。

优化方案 — 分步表单 + 进度指示器

将创建流程拆分为最多 3 步：①基本信息（名称+类型+描述）②参数配置（参数+班级+时间合并）③预览确认。顶部添加步骤进度条（Step 1/3），每步可自由前进后退，数据自动暂存。支持「保存草稿」随时退出。

问题 P1

批量操作入口隐蔽：批量删除/导出功能藏在「更多」下拉菜单中，用户需要先勾选多行才能发现入口，操作路径长。

优化方案

当用户勾选任意一行后，顶部操作栏自动浮现批量操作按钮（删除/导出/分配），并显示已选数量（如「已选 3 项」）。未选中时按钮隐藏，避免干扰。

4.2 反馈机制不足

问题 P0

提交操作后只有短暂的 loading 动画，成功/失败缺少明确的 Toast 提示。删除操作的二次确认弹窗只有「确认/取消」两个按钮，没有说明删除后果。表单验证只在提交时触发，不是实时校验。

优化方案 — 三层反馈体系
层级触发时机表现形式持续时间
即时反馈按钮点击/Hover视觉态变化（按压/高亮）0-100ms
操作反馈提交/保存完成Toast 通知（顶部居中）3秒自动消失
状态反馈异步任务进行中进度条 / Skeleton 骨架屏持续至完成

Toast 规范：成功（绿色 #10B981 + 勾选图标）、失败（红色 #EF4444 + 警告图标）、警告（橙色 #F59E0B + 叹号图标）、信息（蓝色 #2563EB + 信息图标）。
删除确认弹窗：增加后果说明文字（如「删除后该实验及其所有学生数据将无法恢复」），危险操作按钮用红色 Danger 样式。
表单实时校验：输入框 blur 时立即校验，不合规则即时显示错误提示，不等提交。

4.3 可访问性问题

问题 P1

文字对比度不足：辅助文字 #A0AEC0 在白色背景上对比度仅 2.6:1，低于 WCAG AA 标准 4.5:1。可点击区域小于 44×44px（部分表格操作按钮仅 24×24px）。不支持键盘 Tab 导航焦点。

优化方案

对比度修正：辅助文字从 #A0AEC0 调整为 #718096（对比度 4.6:1，达到 AA 标准）。

可点击区域：所有交互元素最小可点击区域 44×44px，表格内的文字按钮通过增加 padding 扩大点击热区。

键盘导航：所有可交互元素添加 :focus-visible 样式（蓝色 outline 2px + offset 2px），支持 Tab 键顺序导航，Enter/Space 触发点击。

4.4 空状态与加载状态

问题 P2

表格无数据时只显示「暂无数据」文字，缺少引导操作。页面加载时使用全屏白屏，没有骨架屏过渡，体验突兀。

优化方案

空状态：展示插画 + 说明文字 + 引导按钮。如「暂无实验记录」+「创建第一个实验」按钮。表格空状态保持表头可见。

骨架屏：页面首次加载使用灰色骨架屏（#F1F5F9 块 + shimmer 动画），结构与实际内容一致。表格加载时展示 5 行骨架行。数据更新时使用局部 loading 覆盖层，不全屏刷新。

5

优先级排序与实施路线

P0 — 必须立即修复

  1. 统一间距体系（8px 基准），修正侧边导航宽度、卡片间距、表格行高
  2. 建立五级文字层次（24/18/15/14/12px），确保层级清晰
  3. 统一配色系统（6:3:1 比例），全站只使用一个品牌主色
  4. 统一按钮四级体系（Primary/Secondary/Tertiary/Danger），每页仅 1 个主操作
  5. 添加操作反馈 Toast 通知，删除操作增加后果说明
  6. 创建流程拆分为 3 步 + 进度指示器，支持前进后退和数据暂存

P1 — 尽快修复

  1. 统一表单规范（输入框高度 36px、标签顶部对齐、必填标记 *、实时校验）
  2. 统一导航三态样式（默认/Hover/选中），添加面包屑导航
  3. 批量操作入口自适应浮现
  4. 可访问性修正：对比度 ≥ 4.5:1、可点击区域 ≥ 44px、键盘导航支持

P2 — 体验提升

  1. 空状态引导（插画 + 引导按钮）
  2. 骨架屏加载过渡
  3. 侧边导航折叠态（64px）
