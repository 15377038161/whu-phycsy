# 武汉大学量子实验教学平台架构

本文档是项目结构真源。修改代码前必须完整阅读。

## 1. 定位与运行方式

平台是 Flask + Jinja 单体应用，面向学生和教师。生产环境由 Docker Compose 启动 Gunicorn 与 PostgreSQL，上传文件存放在挂载到 `/data/files` 的内容寻址目录。学校通过 HTTPS 反向代理访问。

本项目不再依赖 Coze、Supabase、iframe token 或平台专有 SDK。开发环境可使用 SQLite；`APP_ENV=production` 时必须使用 PostgreSQL，禁止回退到 JSON 或 SQLite。

## 2. 代码边界

- `app.py`：WSGI 入口，仅创建应用。
- `platform_app/blueprints/`：`auth`、`student`、`teacher`、`api` 四组 HTTP 入口。
- `platform_app/models.py`：唯一关系模型定义。
- `platform_app/services/`：实验版本、提交、评分、拟合、报告业务。
- `ai_service.py`：OpenAI 兼容 AI 客户端，必须懒加载。
- `templates/` + `static/quantum-platform.css`：唯一 UI；不保留旧页面或并行 CSS。
- `source_docs/`：内部知识来源，不向学生直接公开。
- `static/fonts/simhei.ttf`：中文 PDF 字体，必须保留。

视图不得直接拼 SQL；业务写入必须经服务函数完成。发布后的实验版本、提交修订、AI 评估和教师审核不可原地覆盖。

## 3. 数据规则

PostgreSQL 保存用户、班级（`Course`）、AI 实验草稿、报告活动草稿（`ReportDraft`）、选课、实验、实验版本、冻结试卷、提交修订、教师审核、文件元数据、审计事件和旧数据归档。历史 AI 评估、奖状及旧评分字段只作兼容保留，不再参与新业务。

- 已发布实验版本不可修改，只能复制为新草稿或安全下架。下架只将状态改为 `retired`，学生目录立即隐藏该版本并回退到仍在架的最新发布版本；旧提交、审核、报告和冻结试卷继续绑定原版本，禁止级联删除。
- 学生提交预习答案后，在本次尚未形成实验报告期间固定版本；仅打开页面但尚未作答时可迁移到新的已发布质量修订版。旧版本报告提交完成后允许进入后续发布版本，历史预习、提交和报告继续绑定原版本且不可覆盖。
- 每次提交产生不可变修订；最多撤回两次，旧提交和旧审核保留。
- 教师评分与内部评语不得出现在学生接口、页面或学生报告。
- 文件按 SHA-256 命名，上传后不可覆盖；实验展厅封面、演示视频、PDF 讲义、PPT/PPTX 原文件及其 PDF 预览绑定均随版本发布冻结。已认证媒体入口只允许读取已登记的安全图片、视频、PDF 与演示文稿；PDF 可内联预览，PPT/PPTX 强制下载。
- AI 实验草稿与正式实验版本分离。生成草稿只保存教师可编辑的实验代码、名称、原理、仪器、拟合口径和详细步骤；确认操作才创建 `Experiment` 与首个 `draft` 版本并将 AI 草稿标记为 `confirmed`，不会直接发布。原始材料哈希与生成、确认、删除操作均进入审计链。

## 4. 正式实验

班级通过 Course.min_experiments_required 配置最低大关卡数量，默认 3。学生选择状态和步骤进度保存在 StudentExperimentProgress，按学生、班级和发布版本隔离；服务器在正式提交前校验全部必做步骤完成。单实验采用页面式顺序小关卡，字段支持数值、短文本、单选、多选、数据表格与图片；数据表允许学生追加带名称的自定义列，列定义和数据随步骤保存并同步报告；服务器校验必填项、表格有效行和拟合结果，禁止空数据或越级通关。拟合是同一流程中的独立小关，显式引用前序数据表；在线 Pyodide 失败时可保存 Excel 参数与拟合图。系统块同步到活动报告草稿时如检测到学生已修改对应内容，必须先选择刷新或保留，不得静默覆盖。

核心正式实验集合为：离子阱实验、量子密钥分发、量子纠缠、金刚石量子计算机、单像素光子成像。旧 NV L01-L05 只读归档，不参与新进度。教师可新增教学模块；只有完成统一发布校验并发布的模块才进入学生实验目录。学生首页必须按全部未退役的最新发布版本动态生成数量、编号和卡片，未知实验代码使用统一校园封面，不得依赖五项实验的硬编码数量。

实验目录顺序以 `Experiment.order_no` 为唯一真源。教师调整顺序时必须在同一事务中先归一化为连续序号、再交换相邻实验，并写入 `experiment.reorder` 审计事件；学生目录、首页编号、当前/下一实验选择和教师目录均按该字段排序。教师实验管理页使用固定的纯文本列表，不渲染封面或其他图片，也不展示历史版本时间线；每个条目只提供编辑、整实验复制、发布当前草稿、下架、安全删除与顺序调整。整实验复制必须创建新的 `Experiment` 和独立草稿，不得覆盖源实验。学生端仍保持单行展厅布局。

## 5. UI 与报告

UI 采用“珞珈量子博物馆”全屏布局：暖白纸张底色、武大蓝、玉石青、少量樱花粉。学生和教师共用 `base.html` 中同一套顶部页眉 DOM、官方品牌组合、尺寸、交互与响应式规则，只允许导航项目和角色文案因业务身份不同；禁止再为教师页眉维护独立配色或布局。学生页面只展示预习题得分、报告提交状态和学生自己的实验数据，不显示教师评分、审核决定、通过状态、基于成绩的奖状或任何可反推教师评分的信息。学生完成集中选关后，首页统计、“我的实验”和“报告与荣誉”的实验范围均以已选实验版本为准；完整发布目录只在选关面板中出现。

品牌图形使用武汉大学官网发布的标准校徽、标准组合及珞珈建筑辅助纹样；实验与校园主视觉位于 `static/images/`，其中 `static/images/brand/whu-quantum-linescape.png` 是页面留白、教师主视觉、内容底部和登录表单区共用的珞珈线景。学生与教师外壳使用固定全视口背景层，以 `cover` 等比缩放、底部居中、禁止纵向重复，长页面滚动时始终由同一视口背景覆盖，不得因图片自然高度不足出现下半页留白。同一页面最多展示一次完整建筑全景，后续留白只可使用低透明度的局部山线或量子轨迹，禁止重复平铺完整建筑群。校园照片和建筑线景本体禁止通过裁剪复制层旋转或位移动画，避免屋檐、楼体等细节错位；学生端使用独立樱花飘落、光线变化和量子粒子轨迹，教师端使用樱花粉与克制金色花瓣，登录页花瓣覆盖整个视口。所有动态层均不可接收点击、不可遮挡业务内容，并必须响应 `prefers-reduced-motion`。实验图片只表现设备局部、真实光路与数据结构，不使用虚假人物或实验室宣传照。

页面采用单任务工作台、抽屉和确认弹窗组织复杂流程，不通过无限纵向页面堆叠功能。筛选、目录和辅助信息进入非阻断抽屉；不可逆或会改变正式业务状态的操作才使用确认模态；保存、同步与错误反馈使用通知弹窗。所有弹层由 `static/platform.js` 的统一控制器管理，必须支持关闭按钮、遮罩关闭、Escape 关闭、焦点回归和键盘焦点约束；桌面抽屉从右侧滑入，手机抽屉转为底部面板。学生首页主视觉按冻结预习和提交修订的真实时间选择个人当前实验：优先最近操作的已选实验，没有活动记录时显示已选目录中的第一项。学生首页的“实验展厅”严格保留原版连续展廊空间，不使用独立小岛或闯关地图；标题不绑定实验数量，已选实验卡片固定为单行横向集合，空间不足时通过左右按钮、触控滑动或键盘方向键浏览。学生首页首项统计为“已完成实验”，仅统计已选实验中当前最新且未撤回的正式提交，统计分母为学生当前已选实验数，不使用预习完成数或教师评分。学生端固定为实验探索、我的实验、报告与荣誉：我的实验展示已选实验、本人预习分数与学习进度并支持全部/已完成/未完成筛选；报告与荣誉只保存正式报告归档与已选实验的学习纪念，避免重复目录。实验页提供原理、预习、实验闯关、实验报告的上一步/下一步流式导航。教师端固定为审核、实验管理、学生管理。原始数据使用实验字段驱动的表格录入，系统提供教师发布的可运行拟合代码；代码与图表始终只在浏览器 Pyodide 中执行和生成，学生 AI 不读取数据也不生成拟合代码。

“报告与荣誉”中的荣誉展厅采用浅色二维樱花证书体系：左侧显示当前选中的纪念证书，右侧只显示学生已选实验的纪念牌，数量随选关结果动态变化。纪念证书只在该实验最新有效报告修订状态为 `submitted` 时解锁；撤回后重新锁定。解锁逻辑不得查询 `Review`、旧 `Award`、教师分数或审核决定，页面也不得使用“通过”或按成绩授予等表述。点击任一纪念牌可查看实验说明、解锁条件与学生自己的报告修订记录；动效必须响应 `prefers-reduced-motion`，音效只能作为非关键反馈。

教师实验学情观测台基于教师负责班级批量查询学生、实验版本、预习任务、报告修订和最新有效人工审核，不执行逐学生查询。观测台统一提供班级整体概览、实验任务完成率和学生个体明细，支持班级、实验、任务类型、状态与时间筛选；“停滞预警”定义为任务未全部完成且 7 日没有新学习活动，不得将其表述为教师已设置的截止日期逾期。教师学情 Excel 导出与页面使用同一筛选数据快照；教师 AI 快照继续剔除预习分与教师分数等得分字段。

全平台字体、标题、正文、辅助文字、控件和 Lucide 图标遵循 `UI_VISUAL_STANDARD.md`，功能与接口契约遵循 `FUNCTION_API_PLAN.md`，实现集中在唯一的 `static/quantum-platform.css` 与 `static/platform.js`。所有登录后页面共用返回上级、回到角色首页、跳到主要内容、离线提示、表单错误聚焦和提交中防重复操作；同源历史不存在时返回键必须回到角色首页。教师 UI 同时使用 `TEACHER_UI_SPEC.md` 中的唯一信息架构：审核队列只承担修订审核，学生管理只承担班级名单和账号操作，跨实验完成率、未完成名单与预警只在学情观测台展示。教师数字统一使用等宽数字样式；小屏表格必须转为带 `data-label` 的字段卡片。手机内部报告先呈现人工评分面板，再呈现报告正文，并保留双向快捷锚点；不得通过复制页面或新增平行 CSS 实现移动端。

预习题库按“母题方向 + 不同考法”组织：发布版本至少包含 10 个母题方向和 40 道候选变式。每名学生、课程和实验版本冻结一份独立题卷，题目集合、题目顺序和选项顺序均按学生独立确定；同一班级任何学生当前或历史题卷不得出现完全相同的十题组合。学生提交后答案不可覆盖，页面逐题显示回答对错、正确答案和教师发布解析。重新抽题会把本次完整快照追加到题卷历史，排除该学生所有历史原题后再从相同或其他母题方向选择不同考法；可用变式不足时明确要求教师扩充题库，不得回退复用原题。

教师端“学生管理”只负责创建班级、名单、学习进度与账号安全；学生名单只通过 `.xlsx/.xls` Excel 文件导入，服务器扫描前 30 行和全部工作表，以表头别名及列数据特征识别学号、姓名和可选密码列，列顺序任意且忽略额外字段。识别歧义、缺失关键值或重复学号时必须整批拒绝，禁止猜测错位写入；表中无密码列时，新账号使用教师本次填写的统一临时密码，已有账号加入新班级无需密码。“实验管理”统一负责手动新建、AI 实验草稿、顺序、封面、演示视频和版本生命周期。教师 AI 学情只保留右下角全局浮窗入口，页面内容区不得重复放置同功能按钮。学生端实验操作页展示发布版本中的完整文字操作说明，不把静态步骤伪装成当前进度。

学生端全局 AI 答疑助手只有两项职责：解释当前实验已发布原理，以及在学生忘记时提醒已发布操作步骤和安全注意事项。服务端根据学生课程和实验代码构造公开上下文，禁止接收或转发客户端整页 DOM、预习题、报告、成绩或实验数据。成绩、评分、排名、其他学生信息、预习题/题库答案、原始或具体实验数据、标准值、参考结果、拟合参数等请求必须在模型调用前确定性拒绝；模型提示词同时禁止推断、比较或绕过。允许回答通过 OpenAI 兼容 `stream=true` 上游流逐段读取，再以 `text/event-stream` 转发；响应必须设置 `X-Accel-Buffering: no`，浏览器逐段安全渲染 Markdown/LaTeX，并在中途断开时保留已显示内容且明确提示。学生 AI 拟合代码生成入口已删除，预置拟合方案仍只在浏览器 Pyodide 中执行。

实验报告提交时按发布版本冻结的参考值自动计算数据误差和准确度建议分：误差≤5% 为 100 分，≤7% 为 90 分，≤10% 为 85 分，≤15% 为 80 分，其余为 70 分。该规则是确定性数值计算，不调用模型；结果随不可变报告修订保存，仅在教师审核侧显示并作为人工评分的默认值。最终实验成绩仍以教师对具体修订保存的最新有效 `Review.private_score` 为准；学生只查看自己的预习题得分与逐题解析，不得获取自动准确度分、教师人工成绩、审核决定或内部评语。教师可按自己负责的班级一键导出 `.xlsx` 成绩表，表内按学生和正式实验列出最新有效人工成绩、修订号、审核状态、已评分数、总分和平均分。报告编辑器的题名、摘要、关键词均采用单列编辑流，工具栏在一行内紧凑显示，最终预览仍由统一的 A4 结构化报告数据生成。

教师端 AI 实验创建只接受教师输入和其主动上传的实验材料。PDF、DOCX、TXT、Markdown 在服务器受限解析，单文件不超过 20 MB，提取文字最多 120,000 字符，发送给模型的材料进一步截断；旧版 DOC、加密 PDF、无文本扫描 PDF 和损坏文件必须明确拒绝。浏览器语音只转写为文本，不保存原始音频。AI 返回内容经过代码、名称、原理、详细步骤和拟合字段校验，校验或模型调用失败时不得写入 AI 草稿或正式实验。

每个发布题库必须至少包含 40 题并覆盖不少于 10 个独立知识点，学生抽到的 10 题不得重复知识点。AI 题库必须通过结构、去重、选项长度、无关词、猜题捷径和解析完整性检查；任一题不合格时整批拒绝，不得写入草稿。核心题库质量修订使用新的发布版本，禁止覆盖旧版本。

AI 答复中的 Markdown 与 LaTeX 必须经过先转义、后白名单格式化的客户端渲染流程；数学公式使用 KaTeX，禁止直接插入或执行模型返回的 HTML。公式组件不可用或解析失败时保留安全的源码降级显示。

进入实验闯关页后必须在后台预热 Pyodide，预装 NumPy、SciPy、Matplotlib 与 Pandas，并显示计算引擎、科学计算组件和中文字体三个阶段；进入拟合小关后直接读取前序步骤数据。自定义代码先通过 Pyodide 的导入解析加载其仓库内可用模块，缺失模块必须显示具体名称，不得把学生代码发送到服务器执行。所有加载和执行均设置明确超时；生产环境应配置校内 `PYODIDE_BASE_URL`。在线拟合失败必须显示错误并提供 Excel 参数与结果图兜底，不得静默写入占位结果。`/ready` 可缓存文本与视觉模型探测结果，避免健康检查重复消耗模型额度。

报告正文使用白名单结构化 JSON，不保存或执行编辑器 HTML。每名学生、课程和实验版本只有一个活动 `ReportDraft`；自动保存使用 `lock_version` 乐观锁，提交后草稿冻结。修改历史报告必须复制为活动草稿并产生下一 `SubmissionRevision`，不得覆盖原修订。图片必须先通过当前草稿的安全上传接口登记，正文只能引用该草稿已登记的内容哈希。

编辑器固定学校论文样式，支持受控段落格式、列表、公式、图片、图注和表格；即时 A4 预览用于写作，提交前可调用正式 PDF 渲染器检查精确分页。网页、DOCX 与 PDF 必须读取同一结构化报告模型。学生版不得含教师评分；教师内部版可附审核和修订历史。PDF 生成必须使用 `simhei.ttf` 并经过渲染检查。

### 5.1 当前实验工作台契约

实验页只保留实验原理、预习测试、实验闯关、实验报告四段式导航。演示视频、PDF 讲义及 PPT/PPTX 课件统一归入原理页；操作与拟合不再维护平行页签。实验闯关一次只显示一个小关，允许返回已完成关复查，未完成当前必做关时不得进入后续关。

## 6. 安全与配置

密钥只从环境读取：`AI_BASE_URL`、`AI_API_KEY`、`AI_TEXT_MODEL`、`AI_VISION_MODEL`。`.env.local` 永不进入 Git、镜像、交付包或日志。生产 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`；保留 `ProxyFix` 识别 HTTPS 代理。

浏览器端 Pyodide 执行学生拟合代码；服务器只验证和保存结构化结果，绝不执行学生代码。

所有状态变更请求必须携带与登录会话绑定的 CSRF token：HTML 表单使用 `csrf_token` 隐藏字段，JSON/AJAX 使用 `X-CSRFToken` 请求头。登录按“规范化账号 + `ProxyFix` 解析后的客户端 IP”记录五分钟失败窗口；连续失败五次后锁定五分钟，失败与锁定均写入审计事件。

密码修改与教师重置学生密码均经账户服务校验并写入审计事件。所有上传在流式写入前校验扩展名与 MIME 双重白名单，明确拒绝 SVG、HTML、XML 等可执行文档；封面只接受 JPG、PNG、WebP，视频只接受 MP4、WebM、MOV、M4V，学生附件仅接受已登记的图片和常见文档类型。文件采用 SHA-256 内容寻址，默认上限 500 MB（`MAX_UPLOAD_MB`），生产文件卷必须与数据库同批备份。`/media` 仅内联安全图片/视频类型，其余已登记媒体强制下载，并统一返回 `nosniff`。

应用统一返回 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff` 和限制到本应用及 `PYODIDE_BASE_URL` 源的 CSP；生产环境另返回一年的 HSTS。KaTeX 与 lucide 均位于 `static/vendor/`，不依赖公共图标 CDN；Pyodide 的脚本、连接和 Worker 来源由 `PYODIDE_BASE_URL` 自动加入 CSP。
